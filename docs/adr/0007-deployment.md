# 0007. 배포: 컨테이너 + 국내 리전

- 상태: 제안
- 날짜: 2026-10-28

## 맥락

개인 프로젝트라 비용을 낮게 유지해야 하지만, 실제 기관이 쓰는 서비스라 안정성과 개인정보 보관 위치도 중요하다.
기관 홈페이지는 이미 Cloudflare에 정적 사이트로 배포되어 있고, 그대로 유지한다.

## 선택지

| 방식 | 장점 | 단점 |
|---|---|---|
| 해외 PaaS (가입만으로 배포) | 설정이 가장 쉬움 | 데이터가 해외에 저장되면 개인정보 국외 이전 고지 부담 |
| 국내 리전 클라우드 VM + 관리형 DB | 데이터가 국내에 있음, 구성 자유도 높음 | 직접 관리할 것이 많음 |
| 기관 내부 서버 | 데이터가 기관 안에 있음 | 기관에 관리 인력이 없음 |

## 결정

- 애플리케이션은 Docker 이미지로 빌드한다. 어디로 옮겨도 같은 방식으로 실행되게 하기 위해서다.
- 서버와 DB는 **국내 리전(서울)** 에 둔다. 민감정보가 해외로 나가지 않게 한다.
- 초기 구성: 작은 VM 1대에서 API 컨테이너 실행 + 관리형 PostgreSQL (자동 백업)
- 파일(사진, 서류)은 S3 호환 객체 저장소에 두고, 클라이언트는 짧은 수명의 서명 URL로만 접근한다.
- CI/CD: GitHub Actions에서 테스트 → 이미지 빌드 → 배포. 테스트가 실패하면 배포하지 않는다.
- 비밀값(DB 비밀번호, 암호화 키, JWT 서명 키)은 저장소에 넣지 않고 배포 환경의 비밀값으로 주입한다.
- 구체적인 클라우드 업체와 사양은 비용 비교 후 이 문서에 추가한다.

## 결과

- 얻는 것: 데이터 위치 문제를 처음부터 피한다. 컨테이너로 만들어 두면 업체를 바꿔도 이전이 쉽다.
- 감수하는 것: PaaS보다 초기 설정이 많다. 서버 1대라 장애 시 서비스가 멈출 수 있다 (시범 운영 단계에서는 감수).

## 다시 볼 조건

- 사용 기관이 늘어 서버 1대로 부족할 때
- 비용이 예산을 넘을 때
