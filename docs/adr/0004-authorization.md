# 0004. 권한: 기관 소속 역할 + 리소스 범위

- 상태: 제안
- 날짜: 2026-10-28

## 맥락

같은 기관 안에서도 볼 수 있는 범위가 다르다.
보호자는 자기 가족의 정보만 봐야 하고, 종사자는 담당하는 그룹이나 프로그램만 다루는 경우가 많다.
한 사람이 여러 기관에 속할 수도 있다 (예: 두 기관에서 일하는 종사자).

## 선택지

- 사용자에 역할 하나만 붙이기: 단순하지만 여러 기관 소속을 표현할 수 없음
- 역할 기반(RBAC)만 사용: "보호자" 역할만으로는 "어느 이용자의 보호자인지"를 표현할 수 없음
- 역할 + 리소스 범위: 역할로 할 수 있는 행동을 정하고, 관계로 대상 범위를 좁힘

## 결정

**1단계: 기관 소속 역할**
- 역할은 사용자가 아니라 `소속(membership) = 사용자 × 기관 × 역할`에 붙는다.
- 역할: `ORG_ADMIN`(기관 관리자), `STAFF`(종사자), `GUARDIAN`(보호자)
- 플랫폼 운영자(`PLATFORM_ADMIN`)는 기관 데이터를 직접 보지 않고 기관 생성과 설정만 한다.

**2단계: 리소스 범위**
- 보호자: `보호자-이용자 관계`가 있는 이용자의 데이터만 접근
- 종사자: 담당 그룹 배정이 있는 이용자만 접근 (기관 설정으로 "전체 보기" 허용 가능)
- 민감정보(장애·건강) 열람은 역할과 별도로 권한 플래그를 둔다.

**구현 원칙**
- 컨트롤러가 아니라 서비스 계층에서 검사한다. 같은 서비스를 다른 경로로 불러도 검사가 빠지지 않게 하기 위해서다.
- 권한이 없으면 `403`, 대상이 다른 기관 소속이면 존재 여부를 숨기기 위해 `404`로 응답한다.
- 권한 판단 결과는 접속기록(0005)에 남긴다.

## 결과

- 얻는 것: 여러 기관 소속, 보호자-이용자 관계, 담당 범위를 모두 표현한다.
- 감수하는 것: 조회마다 관계 확인이 필요해 쿼리가 늘어난다. 자주 쓰는 관계는 캐시를 검토한다.

## 다시 볼 조건

- 기관마다 역할 구성이 크게 달라 고정 역할로 감당이 안 될 때 (사용자 정의 역할 검토)
