# 0008. 검증 전략: 불변식 우선 + 다층 검증

- 상태: 제안
- 날짜: 2026-10-28

## 맥락

이 서비스는 기관 간 데이터 격리, 정원과 대기 순번, 토큰 교체, 민감정보 암호화처럼
**한 번 깨지면 곧바로 사고(개인정보 유출, 정원 초과, 계정 탈취)로 이어지는 성질**을 다룬다.
기능이 늘어날수록 예시 몇 개로 확인하는 일반 단위 테스트만으로는 이런 성질의 회귀를 막기 어렵다.
특히 동시 요청에서만 나타나는 버그는 예시 테스트로 거의 잡히지 않는다.

## 선택지

| 방식 | 장점 | 한계 |
|---|---|---|
| 예시 기반 단위 테스트만 | 쉽고 빠름 | 생각한 경우만 검사. 동시성 버그를 거의 못 잡음 |
| 정리 증명기(Coq, Lean 등)로 코드 증명 | 가장 강한 보장 | Java + Spring 코드에 적용하기엔 비용이 과도함 |
| 불변식 우선 + 다층 검증 | 핵심 성질을 여러 각도에서 자동 확인, 현실적인 비용 | 적힌 불변식과 정해진 범위 안에서만 보장 |

## 결정

**불변식 우선 + 다층 검증**을 채택한다.

1. 모든 기능은 불변식을 먼저 `docs/invariants/INVARIANTS.md`에 적는다.
2. 불변식마다 아래 계층 중 하나 이상으로 검증한다.
   - L1 DB 제약: 잘못된 상태를 DB가 저장하지 못하게 한다. 코드 경로와 무관하게 보장된다.
   - L2 성질 기반 테스트(jqwik): 무작위 입력과 무작위 명령 순서로 불변식을 확인한다. 실패하면 가장 작은 반례로 줄여서 보여준다.
   - L3 모델 검사(TLA+/TLC): 동시 실행 흐름을 수학적 모델로 쓰고, 정해진 범위 안의 **모든 실행 순서**를 전수 탐색한다.
   - L4 구조 규칙(ArchUnit): 계층 의존과 테넌트 식별자 누락 같은 구조 위반을 컴파일 후 바로 차단한다.
   - L5 동시성 통합 테스트: L3 모델의 시나리오를 실제 PostgreSQL과 다중 스레드로 재현해, 모델과 구현이 같은 결과를 내는지 확인한다.
   - L6 변이 테스트(PIT): 코드를 일부러 바꿨을 때 테스트가 실패하는지 확인해 테스트 자체의 힘을 잰다.
3. CI에서 모든 계층을 실행하고, 하나라도 실패하면 병합하지 않는다.
4. 버그는 먼저 실패하는 불변식 테스트로 재현한 뒤 고친다.

도구 버전과 변이 점수 기준은 Gradle 프로젝트를 만들 때 정하고 이 문서에 추가한다.

## 결과

- 얻는 것: 적힌 불변식은 기능이 늘어나도 매 커밋 자동으로 지켜진다. 동시성 버그를 구현 전에 모델에서 먼저 찾는다. 면접에서 "회귀를 어떻게 막았나"에 구체적으로 답할 수 있다.
- 감수하는 것: 불변식과 TLA+ 명세를 쓰는 시간이 든다. CI 시간이 늘어난다 (변이 테스트는 도메인 패키지로 범위를 제한).
- 한계: 적히지 않은 성질, 모델 범위 밖의 상황, 외부 시스템 장애는 보장하지 않는다. 그래서 불변식 목록을 계속 늘리는 것이 운영 절차의 일부다.

## 다시 볼 조건

- CI 시간이 개발 속도를 크게 떨어뜨릴 때 (변이 테스트를 야간 실행으로 이동 검토)
- TLA+ 모델과 구현이 반복해서 어긋날 때 (모델 작성 방식 재검토)
